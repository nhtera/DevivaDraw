`<DevivaDraw />` is the complete whiteboard: canvas, tools, toolbar, style
panel, menus, keyboard shortcuts, command palette, touch support. This guide
covers the embedding contract - how a host app feeds it data, reacts to
changes, and drives it programmatically. For what the shell does on its own,
see [Presenting](/guides/presenting/) and
[Touch, Pen & Devices](/guides/touch-and-input/). Here it is embedded with an
`initialData` document, exactly as described below:

## Minimal embed

```tsx
import { DevivaDraw } from "@deviva-draw/react";

<DevivaDraw style={{ position: "fixed", inset: 0 }} />
```

The component fills whatever sized box you give it - `position: fixed; inset: 0`
for full-screen, or any container with an explicit width and height.

## Props

Every prop is optional - the component is complete with none of them.

| Prop | What it does |
|---|---|
| `initialData` | A saved document to load on mount. Supplying it also turns the built-in autosave off: you are the storage layer. |
| `persistenceKey` | Scopes the built-in autosave, so several instances can coexist without overwriting each other. |
| `onChange(elements, files)` | Debounced, after any user-authored scene change - the host integration point. |
| `theme` | `"light"` / `"dark"`. Omit for the visitor's persisted preference. |
| `locale` | `"en"` / `"vi"`. Omit for the persisted preference, then the browser language. |
| `initialViewOnly` | Starts the shell read-only. |
| `shareApiBaseUrl` | The collab server for share links and live rooms. Omit and both disable themselves. |
| `initialRoomUrl` | A room URL to auto-join once on mount. Requires `shareApiBaseUrl`. |
| `fileOperations` | Host-supplied open/save - native dialogs, path identity, save-in-place. See [Desktop App](/guides/desktop/). |
| `onDocumentStateChange(state)` | Fires synchronously on every document identity/dirty transition (`{path, name, dirty}`). Dirty is content-only: pan, zoom and page switching never set it. |
| `offlineHints` | Lets online-only entry points (share, collaborate, AI diagrams) show a "requires internet" hint and disable themselves while offline. |
| `className`, `style` | Standard styling hooks. |

## Loading and persisting data

By default the component autosaves to `localStorage` and restores on mount -
zero-config persistence for a standalone page.

Image data does not go there. An origin gets only a few megabytes of
`localStorage` for everything it stores, and a single photograph, base64-encoded,
can use all of it - so the document (elements, pages, view state) goes to
`localStorage` while the image bytes go to an IndexedDB database named
`devivadraw-files`, keyed by the same content-addressed `fileId` the elements
reference. Files are read back on mount and collected when nothing refers to
them any more. If IndexedDB is unavailable - a private-mode refusal, a locked-down
embedding - the bytes stay in the `localStorage` document, exactly as before.

Saved, exported and shared documents are unaffected: those always embed their
images, because a file that leaves the app has to stand on its own.

**When storage fills up** the browser rejects the write, and a canvas that keeps
accepting edits while saving none of them is the one failure a user cannot see -
until the next reload. A banner says so for as long as saving is broken, offers
to save the work to a file, and retracts itself the moment a write lands again.
It shows even in [zen mode](/guides/presenting/#zen-mode).

**Multiple instances:** scope each instance's autosave with `persistenceKey`
so they don't overwrite each other:

```tsx
<DevivaDraw persistenceKey="board-review-session-42" />
```

**Own your persistence:** pass `initialData` (a previously saved document) and
listen to `onChange`. When `initialData` is supplied, the component never
touches `localStorage` - you are the storage layer:

```tsx
<DevivaDraw
  initialData={savedDocument}
  onChange={(elements, files) => {
    // debounced; fires after any user-authored scene change
    saveToYourBackend(elements, files);
  }}
/>
```

## The imperative handle

Attach a ref for programmatic control:

```tsx
import { useRef } from "react";
import { DevivaDraw, type DevivaDrawHandle } from "@deviva-draw/react";

function Board() {
  const ref = useRef<DevivaDrawHandle>(null);

  const download = async () => {
    const blob = await ref.current!.exportToPng({ scale: 2 });
    // hand the Blob to a download link, upload, etc.
  };

  return <DevivaDraw ref={ref} />;
}
```

The handle's surface:

| Method | What it does |
|---|---|
| `getSceneElements()` | Every live element in z-order - read the scene structure. |
| `getFiles()` | Stored files (images) referenced by live elements. |
| `exportToPng(options?)` | Rendered PNG as a `Blob` (`scale` 1–3, `padding`, `backgroundColor`). |
| `exportToSvg(options?)` | Rendered SVG as a string. |
| `loadSceneDocument(doc)` | Replace the scene with a saved document - returns `false` on invalid input, never throws. |
| `openDocument(text, path, options?)` | Programmatic file open with document identity; `preserveCamera` keeps the viewport steady. |
| `saveDocument(options?)` | Runs the save flow; resolves with the outcome. |
| `resetScene()` | Clear the canvas (a single undo step). |
| `undo()` / `redo()` | History control. |
| `zoomToFit()` | Frame all content in the viewport. |
| `runAction(actionId)` | Dispatch any registered action - the same path the menus and command palette use. |

## Theme and language

```tsx
<DevivaDraw theme="dark" locale="en" />
```

- `theme`: `"light"` or `"dark"`. Omit to use the visitor's persisted
  preference (defaulting to light). Sync this with your app's theme toggle.
- `locale`: `"en"` or `"vi"`. Omit for the persisted preference, then the
  browser language.

## View-only mode

```tsx
<DevivaDraw initialViewOnly />
```

Starts the shell read-only - no properties panel or context menu. This is how
the built-in share-link viewer renders snapshots.

## Enabling share & collaboration

Share links and live multiplayer need a collab server to talk to:

```tsx
<DevivaDraw shareApiBaseUrl="https://collab-draw.deviva.app" />
```

Omit it and both features disable themselves gracefully. See
[Collaboration](/guides/collaboration/) for the full story, including
`initialRoomUrl` for auto-joining a live room on mount.

## Building your own chrome

The composed component is one option. The package also exports the lower-level
building blocks it is made of - `ThemeProvider`, `ActionRegistry`,
`createCameraStore`, `useTextEditing`, `usePasteAndDrop`, and more - for hosts
that want the engine with custom UI around it. Start from the
[engine guide](/guides/engine/) and the package's typed exports.
